# 연세 매칭 — 기획 & 기술 문서

연세대학교 교내 데이팅(매칭) 서비스의 PRD·와이어프레임을 바탕으로 한
**기술 검토 및 구현 계획** 문서 모음입니다.
**1인(비개발자) 창업자**가 AI(클로드)의 도움으로 만들고, **직접 클릭해
테스트**하는 상황을 전제로 작성되었습니다.

> 이 문서들은 "어떻게 만들지"에 대한 합의서입니다. 코드는 제(클로드)가 쓰고,
> 창업자님은 살아있는 화면을 눌러보며 확인하는 방식으로 진행합니다.

## 한 줄 정의

연세대학교 교내 구성원 한정 데이팅 서비스. 주 1회 설문 기반 매칭.

## 핵심 컨셉 (PRD 요약)

- **주 1회 시스템 매칭** — 스와이핑 피로도를 없앰
- **@yonsei.ac.kr 이메일 인증** — 교내 구성원만, 신뢰·안전성 확보
- **40문항 설문**(가치관 · 성격/성향 · 연애관) 기반 정밀 매칭
- **이메일 중심 소통** — 이름·연락처 비공개, 정보 유출 리스크 최소화
- **웹 대시보드** — 매칭 히스토리/일정/피드백 확인
- 매칭 결과·만남 가이드는 이메일로 발송

## 와이어프레임 화면 (21개)

랜딩 → 회원가입 → 이메일 인증 → 로그인 → 설문 안내 → 가치관 문항 →
성격/성향 문항 → 연애관 문항 → 설문 완료 → 대시보드 → 매칭 현황 →
매칭 히스토리 → 만남 가이드 → 피드백 센터 → 매칭 피드백 → 피드백 완료 →
결제 센터 → 결제 안내 → 결제 진행 → 결제 완료

이 화면들은 단순 랜딩이 아니라 **인증·설문·매칭·이메일·결제**가 모두 얽힌
트랜잭셔널 웹앱임을 의미합니다.

## 결정 로그 (2026-06-19)

| 항목 | 결정 | 메모 |
|---|---|---|
| 팀 구성 | **1인 / 비개발자** | 코드는 AI가 작성, 창업자는 클릭으로 수동 테스트 |
| 호스팅 | **Vercel** | 가장 단순한 배포, 푸시하면 자동 배포 |
| 결제사 | **토스페이먼츠(TossPayments)** | 편의성·문서 품질 기준 선택 (포트원도 가능) |
| 결제 모델 | **정기결제(자동청구) 우선**, 주 1,900원 | 1회 결제는 추후 옵션. "대학생은 돈이 없다" → 저가 정책 |
| 코딩 방식 | AI 구현 + 클릭 검증 | 자동화 테스트보다 **단계별 수동 확인 체크리스트** 위주 |

### 검토 권장 (제안 — 최종 결정은 창업자님)

- ⚠️ **주 단위 자동청구는 PG 수수료 손실이 큽니다.** 1,900원을 매주 따로
  결제하면 건당 카드 수수료가 비중을 크게 차지합니다. 매칭 주기는 **주 1회로
  유지**하되, **청구는 월 단위(예: 4주권 ≈ 7,600원/월)로 묶는 것**을 권장합니다.
  사용자 입장에선 "주 1,900원꼴"로 안내하면 체감은 동일합니다.
- 자세한 근거는 [`tech-stack.md`](./tech-stack.md) 한국 특화 리스크 ①번 참고.
