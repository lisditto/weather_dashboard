# 상세 구현 계획

**읽는 분:** 비개발자 1인 창업자.
**전제:** 코드는 제(클로드)가 작성하고, 창업자님은 **살아있는 화면을 직접 눌러보며**
확인합니다. 이 문서는 "무엇을, 어떤 순서로 만들고, 각 단계에서 무엇을 눌러
확인하는가"를 정리합니다.

---

## 개발 진행 방식 (이렇게 같이 일합니다)

1. **제가 기능을 하나씩 구현**합니다.
2. 코드를 올리면 **Vercel이 자동 배포**해 곧바로 열어볼 수 있는 **링크(URL)**가 생깁니다.
3. 제가 드리는 **"직접 확인 체크리스트"**대로 화면을 눌러봅니다.
4. 이상하거나 마음에 안 들면 **그대로 말씀**해 주세요 → 제가 고칩니다.
5. 통과하면 **다음 기능**으로 넘어갑니다.

> 핵심: 한 번에 다 만들지 않습니다. **작게 만들고 → 눌러보고 → 다음**의 반복입니다.
> 그래서 비개발자도 매 단계 "지금 어디까지 됐는지"를 눈으로 확인할 수 있습니다.

---

## 오직 창업자님만 할 수 있는 일 (제가 대신 못 하는 것)

코딩은 제가 합니다. 하지만 **본인 명의·계정·법적 책임**이 필요한 아래는 직접 하셔야 합니다.
(전부 제가 화면 보며 단계별로 안내합니다.)

| 할 일 | 시점 | 비고 |
|---|---|---|
| GitHub · Vercel · Supabase · Resend · TossPayments **계정 생성** | 시작 시 | 무료로 시작 |
| 각 서비스의 **키(비밀번호 같은 것)**를 제게 안전히 전달 | 단계마다 | Vercel 환경변수에 입력 |
| **도메인 구매** + 이메일 발송용 **DNS 설정** | 이메일 단계 | 제가 입력값을 그대로 드림 |
| **개인사업자 등록** + **토스 정식 계약** | 실결제 직전 | 개발/테스트는 테스트키로 선진행 |
| **개인정보처리방침·이용약관 검토/승인** | 출시 전 | 초안은 제가 작성, 최종 책임은 본인 |
| **설문 40문항 최종 확정** | 설문 단계 | 와이어프레임 예시를 토대로 다듬음 |
| **클릭 테스트 & 피드백** | 매 단계 | 가장 중요한 본인 역할 |

## 단계별 계획

각 단계는 **독립적으로 눌러서 확인**할 수 있게 설계했습니다.
순서는 "가치를 빨리 보고 + 위험을 먼저 제거"하도록 짰습니다.

### Phase 0 — 기반 세팅 (토대)
**무엇을:** 빈 Next.js 앱을 만들어 Vercel에 올리고, 계정 5개를 연결합니다.
디자인 기본(색·폰트·버튼 등)을 잡습니다.
**직접 확인:**
- [ ] 제가 드린 **주소를 열면** "준비 중" 페이지가 휴대폰에서 제대로 보인다.
- [ ] Supabase 대시보드에 로그인해 **빈 프로젝트**가 보인다.

### Phase 1 — 랜딩 페이지
**무엇을:** 와이어프레임의 랜딩(브랜딩·소개·"시작하기" 버튼)을 모바일 우선으로.
**직접 확인:**
- [ ] 휴대폰에서 랜딩을 위→아래로 스크롤하면 소개 카드들이 보인다.
- [ ] "지금 시작하기" 버튼을 누르면 회원가입으로 이동한다.

### Phase 2 — 회원가입 / 로그인 / 이메일 인증  ⭐위험 먼저 제거
**무엇을:** `@yonsei.ac.kr`만 가입 가능 → **6자리 코드 메일 발송** → 코드 입력 →
비밀번호 설정 → 로그인 → 비밀번호 찾기. (여기서 **이메일 도달률**을 일찍 검증)
**직접 확인:**
- [ ] 내 연세 이메일로 가입 → **6자리 코드 메일이 실제로 도착**한다.
- [ ] 코드를 넣으면 다음으로 넘어가고, **틀린 코드는 거부**된다.
- [ ] 코드 타이머가 줄어들고 "재전송"이 동작한다.
- [ ] **연세 이메일이 아니면 가입이 막힌다.**
- [ ] 로그아웃 후 다시 로그인된다.
- [ ] Supabase 대시보드 **유저 목록에 내가 보인다.**

### Phase 3 — 설문 (40문항, 다단계 + 자동저장)
**무엇을:** 가치관 · 성격/성향 · 연애관 파트로 나뉜 설문. **중간에 나가도 자동 저장**,
나중에 이어서/수정 가능, 완료율 표시.
**직접 확인:**
- [ ] 설문을 시작해 몇 개 답하고 **창을 닫았다 다시 와도 답이 남아있다.**
- [ ] 끝까지 답하면 **"설문 완료" 화면**이 뜬다.
- [ ] 완료율 막대가 올라간다.
- [ ] Supabase에서 **내 응답 데이터가 저장**된 걸 표로 확인한다.

### Phase 4 — 대시보드 + 매칭 현황/히스토리 (보여주기)
**무엇을:** 로그인 후 대시보드. 매칭 상태 카드, 다음 매칭일, 히스토리 목록, 피드백/
결제 요약. (이 단계는 **화면만** — 실제 매칭 계산은 Phase 5)
**직접 확인:**
- [ ] 로그인하면 **내 대시보드**가 보인다.
- [ ] "다음 매칭일", "매칭 상태"가 표시된다.
- [ ] 히스토리·매칭 현황 화면으로 이동된다.

### Phase 5 — 매칭 엔진 + 주간 배치 + 결과 메일 + 만남 가이드  ⭐핵심 가치
**무엇을:** 설문 응답으로 **호환도를 계산**해 상대를 매칭. "매주 월요일"에 자동
실행(+테스트용 **"지금 실행" 버튼**). 매칭 결과·만남 가이드를 **이메일 발송**.
만남 가이드 화면(공통점/대화 주제) 구현.
**직접 확인:**
- [ ] 테스트 계정 2개로 설문을 채운 뒤 "지금 매칭 실행"을 누르면 **서로 매칭**된다.
- [ ] **매칭 결과 메일이 도착**하고, 내용에 만남 가이드가 들어있다.
- [ ] 대시보드의 매칭 현황이 "매칭 완료"로 바뀐다.
- [ ] 만남 가이드 화면에 **공통점·추천 대화 주제**가 보인다.

### Phase 6 — 피드백
**무엇을:** 만남 후 평점(성실성·대화·외모·시간약속) + 재매칭 의향 + 자유의견.
피드백 센터/완료 화면. (이 데이터는 이후 매칭 정확도 개선에 사용)
**직접 확인:**
- [ ] 매칭 뒤 **피드백을 작성·제출**하면 "완료" 화면이 뜬다.
- [ ] 피드백 센터에서 **완료/대기 상태**가 구분돼 보인다.
- [ ] Supabase에 **피드백이 저장**된다.

### Phase 7 — 결제 (토스 자동결제)
**무엇을:** 토스 **테스트 키**로 결제 센터/안내/진행/완료 화면. **자동청구(빌링)**
연결 → 매주(또는 권장: 매월) 자동 결제. 영수증 메일. 미결제 시 매칭 제외 처리.
**직접 확인:**
- [ ] **토스 테스트 카드**로 결제하면 "결제 완료" 화면이 뜬다.
- [ ] 대시보드에 **멤버십 상태·다음 청구일**이 표시된다.
- [ ] **영수증 메일**이 도착한다.
- [ ] (자동청구) 다음 주기에 **자동으로 재결제**된다(테스트 모드로 확인).

> 💰 가격 정책: 주 1,900원. 단 **수수료 효율을 위해 "월 단위 묶음 청구"를 권장**합니다
> (자세한 이유는 `tech-stack.md` 리스크 ①). 최종 결정은 창업자님 몫이며, 어느 쪽이든
> 구현 가능합니다.

### Phase 8 — 개인정보 보호 + 출시 준비
**무엇을:** 개인정보처리방침/약관 + **가입 시 동의 절차**, 오류 알림(Sentry),
실제 도메인 연결, 토스 **실결제 키로 전환**, 최종 점검.
**직접 확인:**
- [ ] 가입 시 **동의 체크** 없이는 진행되지 않는다.
- [ ] 처음부터 끝까지(가입→설문→매칭→메일→피드백→결제) **한 명의 사용자처럼
      전체를 통과**해 본다.
- [ ] 실제 도메인 주소로 접속된다.

## 데이터 구조 개략 (어떤 정보를 저장하나)

비개발자용 쉬운 설명입니다. 실제 표 이름/구조는 만들면서 확정합니다.

| 저장 묶음 | 담는 내용 |
|---|---|
| 회원 | 연세 이메일, 비밀번호(안전 암호화), 가입일, 인증 여부 |
| 인증코드 | 6자리 코드(암호화), 만료시각 — 검증 후 폐기 |
| 설문 문항 | 40문항 질문/선택지 (수정 가능하게 분리 보관) |
| 설문 응답 | 회원별 답변, 작성중/완료 상태, 자동저장 |
| 매칭 | 누구와 누가 언제 매칭됐는지, 호환 점수, 상태 |
| 피드백 | 매칭별 평점·재매칭 의향·자유의견 (상대에겐 비공개) |
| 결제/구독 | 멤버십 상태, 다음 청구일, 결제 내역(토스 연동) |

> **개인정보 최소 원칙:** 이름·전화번호는 받지 않습니다(제품 컨셉 그대로). 매칭
> 상대에게도 개인정보는 공개되지 않고 **이메일로만 연결**합니다.

## 매칭 알고리즘 개략

- **처음엔 단순하게:** 설문 답변을 항목별로 비교해 **가중치 기반 호환 점수**를 계산
  (가치관·연애관은 "비슷할수록" 가점, 일부 성향은 "보완될수록" 가점 등). 복잡한
  AI/머신러닝은 **필요 없습니다.**
- **점점 똑똑하게:** Phase 6의 피드백(재매칭 의향·만족도)이 쌓이면 가중치를 조정해
  정확도를 높입니다.
- 규모가 한 캠퍼스(최대 수만 명)라 계산 부담이 작아, 주 1회 배치로 충분합니다.

## 출시 전 최종 체크리스트

- [ ] 전체 플로우(가입→설문→매칭→메일→피드백→결제) 한 번에 통과
- [ ] 이메일이 **네이버/구글/연세 메일**에서 스팸함 안 가고 도착
- [ ] 개인정보처리방침·약관 게시 + 가입 동의 절차
- [ ] 개인사업자 등록 + 토스 **실결제** 전환 완료
- [ ] 실제 도메인 연결 + 모바일에서 전 화면 점검
- [ ] 오류 알림(Sentry) 작동 — 문제 생기면 바로 알 수 있게
